## Coverage limits

- The alternate `data-studio-backend/app/connections_api.py` foundation is not registered by `voice-auth-backend/server.py`; its README identifies the voice-auth studio routes as active. Do not separately expose that legacy blueprint.
- Science training receives browser-provided rows, not a dataset ID; its in-memory model artifacts are actor-scoped and expiring. No new object mutation authority is inferred from model training.
- Catalog filtering added in Python is defense in depth. Pipeline/job/output TOP(100) and scheduler history TOP(150) still happen first in legacy SQL; completeness/count/pagination requirements are **not satisfied**. Connection/Dataset lists in the inspected full gateway have no SQL ownership filter.
- Existing object edit/run checks are in service methods. SQL mutation and authorization are separate calls: revocation can race a mutation. A future transactional SQL authorization path is required.
- No dataset update/delete, connection delete, pipeline delete, separate export/download API appeared among these studio route files. Parquet deletion is a separate owner-only path. Private reader HTTP endpoints use service tokens and must remain inaccessible to browsers; those tokens are not per-object authorization.
- Pipeline `call`, ingest `call`, and other low-level RPC methods remain private internal transport APIs; direct gateway/procedure access must not be exposed to clients. SQL data-plane actor attestation remains unresolved.
- Chart metadata get checks both chart and dataset/output access. List rows are chart-filtered but nested config/dependency metadata requires SQL-side review. Dataset catalog includes connection labels; dataset sharing must have an explicit policy for disclosure of referenced connection metadata.
- Sources, direct preview, chart query, and worker source binding require separate CONNECTION read access before secret resolution. Granting DATASET access alone does not grant its source connection. This conservative policy needs UX/product validation before shared access activation.
- ETL output UUIDs are `pipeline_output_version.output_version_id`, not DATASET IDs. Backend policy inherits PIPELINE access through server-resolved run metadata. Owner avatars do not establish output data permissions. SQL/worker consistency still needs DEV trials.
- Ownership GET in 027 restricts share details to owner/admin. Shared-user avatars may therefore fail to hydrate for recipients. This candidate does not change the approved picker/theme code.
- `modules.tsx` marks Dashboard Designer as `planned`. No persistent Data Studio dashboard route/catalog was established by this inventory. Existing legacy/custom dashboard code is unchanged.
- Background scheduler (`spSchedulerDispatch`) queues as `scheduler_schedule.created_by`; workers execute as recorded `requested_by`, never as a browser-supplied actor. Pipeline worker now checks PIPELINE execute before recovery/binding; ingest worker checks DATASET execute before source binding. Dataset and connection rights are checked during binding. Worker lease APIs still require deployment isolation and SQL permissions. Scheduler SQL has legacy creator/active-user validation, not new grant validation. Rights revoked during an already-running Spark process are not actively cancelled.
